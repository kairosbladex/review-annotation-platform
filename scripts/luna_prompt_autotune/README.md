# Luna 复检分类型提示词自动迭代（Hermes Agent）

服务器 ai-lingxi 上按定时任务循环：执行器用 Luna 跑一整轮评测 → Hermes 看结果和错判拼图、写报告、改类别定义卡并提交下一版 → 执行器再跑。
目标是提高各类别准确率、减少“看不清”（uncertain），不改测试环境；线上替换须人工在锁定集上复核后另行决定。

## 组成

| 文件 | 作用 |
|---|---|
| `build_dataset.py` | 本地组装数据：有标签池按事件切 dev（Hermes 可见）/holdout（锁定）；09-24 快照未用事件做无标签池 |
| `prompts/p000.json` | 线上旧提示词（基线，组装结果与测试环境逐字一致）；服务器上另有 `p000b`（基线重复跑，估计随机波动） |
| `prompts/p001.json` | 人工第一版分类型定义卡：违建=蓝/绿色顶棚、光斑须在光伏板上、道路裂纹定义、其余按俯拍外观与易混物体 |
| `promptlib.py` | 提示词组装（只放入本图出现类别的卡，固定结尾保证输出格式不变）与校验（长度、禁止“必须输出true”类句子） |
| `luna_experiment_worker.py` | 实验 worker：保持测试 worker（816cc81）的图像处理方式，提示词随请求传入；增加实际 CLI 输入与结果证据，只监听本机实验端口 |
| `input_evidence.py` | worker/runner 共用的输入证据协议：原始字节、实际附件、裁剪几何、执行/结果绑定和可比输入摘要 |
| `runner.py` | 执行器：停止条件、资源与共享服务检查、跑一轮、打分、拼图；新最好版本才跑 holdout（结果写 `human/`，Hermes 看不到） |
| `metrics.py` | 合格标准：冻结清单与完整覆盖 G0；保留原 G1—G4；人员/道路裂纹误拒与误放双向约束 G5；共同有效框仅作诊断 |
| `samples.py` | 错判拼图（每类每种错误 ≤12 个框，标人工标签和模型结论） |
| `mcp_server.py` | Hermes 可用的工具：读状态/结果、看拼图、读/提交提示词、写报告/台账、提建议 |
| `prompt.md` | Hermes 每次唤醒的步骤与改卡原则 |
| `run_brain_tick.sh`、`systemd/` | 定时器：执行器每 5 分钟；大脑每 10 分钟检查，只有需要时才加载模型 |

## 合格标准与失败语义（2026-10-12）

| 门禁 | 通过条件 |
|---|---|
| G0 | 至少两次基线与候选的开发/无标签池输入清单、样本 key 和标签一致；所有应计分框完整且结果合法；实际图片/裁剪附件、请求模型和输入处理实现相同且证据完整。开发集不能为空 |
| G1 | dev 总体准确率高于两次基线中较高者 |
| G2 | 基线至少 10 框的类别，准确率不低于两次基线较低者 3 个百分点以上 |
| G3 | 人员假目标误放不超过两次基线较多者 +3（保留历史规则；同时受更严格的 G5 约束） |
| G4 | 无标签池 uncertain 比例不高于两次基线平均；三方都没有无标签池时此项不适用，缺结果不能按零 uncertain 处理 |
| G5 | 人员、道路裂纹分别至少 10 框且均有正负例；真目标误拒与假目标误放分别不超过两次基线较差值，不额外增加容忍量 |

- G5 复用类别卡别名（如“人”“路面裂纹”）；10 框且包含正负例只是最低证据要求，不代表统计充分。缺类别、缺正例、缺负例或计分不完整均报告 `insufficient_evidence`（证据不足），不会默认通过。
- `score` 保留原 `accuracy` 等指标口径：只有 `true` 放过，`false/uncertain` 均驳回；新增应评框数、覆盖率、真假交叉表、真目标保留率和假目标误放率。这里的保留率不是整图检测召回率。
- 缺失或非法输出单列为执行失败，不计模型对错，也不能退出分母后继续参与自动选优。总体及逐类显示 `expected_n`（应评框数）；`coverage` 保存缺失/非法 key 与清单摘要。
- `evaluation_sha256` 绑定开发/无标签池的输入清单与标签，包括清单里的图片哈希、候选顺序和坐标。它本身不证明实际输入一致；现在必须同时通过下述 `input_evidence` 校验。严格同帧的业务绑定仍需独立证据。
- runner 单独绑定锁定集身份，拒绝更换清单后复用旧输出续跑；锁定集结果仍仅写 `human/`。只读取当前清单对应的输出文件，重复/错配 key 不能补齐缺框；失败图片、缺文件或缺框均阻止晋级。
- `paired_baselines` 仅对共同有效框作配对诊断，标记 `diagnostic_only=true`；不能用这部分子集绕过完整覆盖门禁。MCP 返回覆盖状态、门禁原因和该诊断，不返回 holdout 结果。
- `is_new_best` 只代表开发集选优，且锁定集执行必须完整后才更新 `best.json`；**不代表锁定集效果达标，更不构成发布授权**。

### 实际模型输入证据（协议 v1，门禁 v3）

成功执行的逐图输出保留 `request_identity`、`execution_id`、`requested_model` 和 `input_evidence`。证据对应本地 CLI 的实际 `-i` 附件，不是事后重新生成的展示图：

- `source`：接收原始字节的哈希、字节数和尺寸；与重新编码后的 `source.jpg` 分开记录。
- `attachments`：按 CLI 提交顺序保存 source/locator/crops 的实际 JPEG 哈希、字节数、尺寸及原始来源哈希。执行前后核对附件未变。
- `crops`：每个原编号目标的归一化框、Pillow 实际取整后的像素裁剪框、缩略图尺寸与拼图位置。**裁剪来自解码后的请求原图，不来自第四张干净辅助图。** 上下文范围和 JPEG 编码均保持原有算法。
- 提示词、候选框、输出 schema、worker/证据模块源码均保存摘要；执行编号与消费的决策、理由、观察对象、图像限制字段绑定。实现摘要在模块加载时冻结，源码文件变化但进程未重启时，健康检查和执行均拒绝通过，避免把磁盘新文件误当成已加载代码。
- 只记录摘要、尺寸与几何，不保存认证信息、绝对路径或额外图片副本。证据摘要用于检测错配/内容变化，**不是远端执行签名**；它不认证 CLI 二进制版本，`requested_model` 也只是请求模型，不是上游实际模型身份的认证。

runner 的防护：

1. 用 `/health` 的 `input_evidence_version` 检查协议兼容性；旧 worker 在调用模型前被拒绝。worker、runner、`input_evidence.py` 必须配套升级，不能只替换一端。
2. 逐图预检实际原图哈希；已声明哈希不匹配时不调用模型。即使旧清单没有图片哈希，也记录本次实际字节，禁止换图片/提示词/候选框后复用旧输出。
3. 验证返回证据与本次请求、执行编号及结果一致；证据错误保存为 `input_evidence_invalid`，不盲目重试，并停止发送本轮后续请求。已经在途的请求允许收尾；资源不足时仍优先中断。
4. 聚合 `input_evidence.complete`（是否全覆盖）和 `inputs_sha256`（实际输入摘要）。提示词、执行编号和结果可变；图片/裁剪、请求模型、输出 schema、输入处理实现必须与两次基线一致。缺证据、缺文件、错配或输入漂移均不能晋级。
5. holdout 证据仍只写 `human/`，不会通过 MCP 暴露留出集详情。MCP 提供开发/无标签池的证据完整性及失败原因。

可选 `clean_image` 仍可用于独立诊断，但只标记为 `clean_auxiliary` / `unverified`。调用方自行传入“已同帧”标记不会被采信，正式 runner 拒绝将这种未核验辅助图纳入自动选优。当前代码没有新增自动配帧、真实视频查询或共享环境写入，**不能据此宣称严格同帧问题或线上效果已经验证通过**。

### 历史记录与升级边界

旧汇总仍可读取，旧准确率不改写。没有覆盖证据/冻结身份/实际输入证据的汇总不能直接通过 G0；已有输出没有绑定冻结清单时，runner 拒绝自动绑定当前清单续跑。旧 `best.json` 缺少当前身份或门禁版本时不会被静默覆盖，也不能通过事后生成附件哈希把历史调用冒充为已审计执行。

需要实际恢复迭代时，先确认独立冻结评测清单和关键类别正负金标，在独立评测轮次中建立两次完整基线；保留旧输出作诊断，**不复制新哈希给旧输出冒充已核验，不自动重跑或改标签**。本次代码变更没有启动模型、更新服务器定时器或部署共享环境。

## 已知局限

- 每轮单次调用。同一提示词跑两次（p000、p000b）有 15.4% 的框结论翻转，dev 准确率 73.0% / 71.2%、无标签 uncertain 45.2% / 39.3%，合格标准因此按两次基线的范围设定。
- Hermes 只看到 dev，反复迭代仍可能过拟合 dev；最终结论以 holdout 为准。
- 道路裂纹 197 框单人金标已能揭示误拒问题，但尚未完成独立复核，也未并入冻结开发集；不能只用 uncertain 下降判断该类别改善。详见上述重算报告和 G5 证据要求。

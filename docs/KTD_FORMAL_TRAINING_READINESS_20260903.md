# KTD 正式训练前数据与金标准审查

> 日期：2026-09-03
> 审查对象：`ktd-uncertain-recheck-20260903`
> 结论：阻塞，暂不具备正式训练条件

## 一、审查结论

当前数据可以用于继续做环境和训练链路验证，但不能直接作为正式训练集或正式验证集。主要阻塞项是：

1. 751 个候选全部为模型伪标签，`human_confirmed` 为 0；
2. `training_manifest.jsonl` 为空，没有人工确认的金标准样本；
3. 10 个类别中只有 7 个类别有正伪标签，`光伏板`、`公交车`、`没戴头盔` 没有正样本；
4. 106 张图中存在 3 组重复图片内容，其中 1 组跨越 train/val，当前划分存在验证泄漏风险；
5. 当前 smoke 使用的矩形 polygon 是由 bbox 临时转换而来，不是真实分割掩码。

因此，上一份 1 epoch GPU smoke 只能证明训练链路可运行，不能证明模型准确率，也不能作为正式模型发布依据。

## 四、数据泄漏风险

原图的 `image_id` 和 object key 都没有重复，train/val 的 image ID 也没有交集。对下载后的图片内容计算 SHA-256 后发现 3 组重复内容：

| SHA-256 前缀 | train 图片 | val 图片 |
|---|---|---|
| `0f82ef8d...` | `img-808d066465cf4c2780e85993` | `img-b32fa0e507b61b6c48ec6ab4` |
| `5eb28156...` | `img-2c2629731f560b434a7293fe`、`img-56ce97d709cac1a455e5c17a` | 无 |
| `a8a10361...` | `img-7f382ddb5c80a4a732eea5a5`、`img-eeaa2f2a6b8c2dfb91bc763d` | 无 |

正式训练必须按图片内容 SHA-256 进行分组后再划分，保证相同内容不会同时出现在 train 和 val。上表的跨集合重复样本应合并、移出验证集，或重新按内容分组划分；在修复前不能使用当前 85/21 划分计算正式指标。

## 五、标签任务不匹配

源 `yolo_labels/` 是 5 列检测框标签，而可用的 `yoloe-v8l-seg-pf.pt` 是 `segment` 模型。为完成 smoke，独立目录 `data/ktd-smoke-seg-dataset-20260903/` 将 bbox 临时表示为矩形 polygon，训练链路因此跑通，但这些 polygon 不代表真实目标轮廓。

正式训练前必须二选一：

- 准备人工确认的真实分割 polygon，继续使用 `segment` 任务；或
- 获取与检测框标签匹配的检测任务权重和训练配置，按 `detect` 任务训练。

不能把 smoke 的矩形 polygon 当成正式分割标注，也不能用分割权重强行解释为检测模型。

## 六、解除阻塞条件

正式训练启动前建议完成以下门槛：

1. 建立人工确认队列，至少为所有纳入训练范围的类别提供人工确认正样本，并让 `training_manifest.jsonl` 非空；
2. 单独准备人工确认的验证集，验证集不能只来自模型伪标签，也不能与训练集共享相同图片内容；
3. 按 SHA-256 做内容分组后重新划分 train/val，重新生成清单并记录划分版本；
4. 明确 `false` 的 37 个 hard negative 如何进入检测训练，不能把 false 框写成正样本；
5. 确认正式任务是检测还是分割，使用匹配的标签格式、权重和配置；
6. 重新执行数据审查，确认类别覆盖、标签边界、图片哈希和血缘信息后，再开始正式多 epoch 训练。

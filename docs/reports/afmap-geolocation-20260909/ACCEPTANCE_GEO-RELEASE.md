## 已上线的行为

- 定位请求读取最新轨迹；Java轨迹批次等待从5秒降为250ms，并冻结入队前快照。
- 正式定位最多允许1秒姿态时差，同时检查运动、近水平视线、交点距离和扰动敏感性。位置质量不合格时保留预警及图片框，目标点不进入地图。
- 四个实时/事后入口保持框与请求顺序一致，按index合并结果；网络/HTTP/格式失败保留事件，短时等待同帧数据后最多重试3次。
- 定位结果保存算法版本、输入/相机/策略指纹、所选姿态时间及质量状态。旧坐标缺追溯信息时默认未核验，原数据库值保留。
- Java实现fe2cba17f0已发布；8181实现316135f于16:08随后发布。没有push；原prod检出未改。8188、8189、Triton的容器与启动时间未变。

Java关闭/初始化较慢，发布期间入口曾出现502，随后恢复；没有强杀进程。当前浏览器可正常到登录页，缺登录会话，未宣称地图图层刷新已视觉验收。

## 历史治理的范围与边界

16:11:09（UTC+8）快照覆盖3,205条有任务归属且保存位置的事件、6,634条非空坐标附件；其中248附件没有任务归属，保持原值。快照之后新增数据不混入本次历史统计。

扫描124份保留日志，恢复215组原请求/响应。对任务、曝光时间、存储坐标及原图片框逐项匹配后，额外155事件具备可回放输入；其中144事件产生逐框质量结果，11事件因缺相邻姿态被拒绝。

还检查了backend的backup、om和复盘日志目录：271份复盘日志约2.9MB中没有bboxes_xyxy、focal_mm、sensor_w_mm、shot_time_ms或log_url；app.log_bak也没有定位框请求。该检查没有找回可用于补足剩余事件的完整定位原请求，详见history-recheck-archive-probe.json与history-additional-archive-inventory.json。

新增144事件合计637个目标：568通过、69拒绝。其中510个已有目标经纬度改变，44个原先定位失败的目标恢复坐标，14个坐标不变而补齐元数据。69个拒绝目标包含16个近水平、42个敏感性超限、11个交点位于相机后方；均不再输出可靠点。

## 后端/设备侧还需提供或确认

1. 更早的定位原请求、原始算法回调和对应轨迹归档。当前logback配置MAX_HISTORY=5，仅有轨迹文件不足以恢复当时镜头、变焦、图像转换和框协议。
2. 各供应方及中间适配版本的x/y定义，原始分辨率、裁剪/缩放/补边，以及定位框锚点。不能把所有旧框统一平移半个宽高。
3. 曝光、GNSS、机体和云台各自的采样时间与时钟同步；本次新增的服务器接收时间不能替代曝光时间。
4. 镜头内参、实际镜头和变焦、AGL/绝对高程/地面高度语义，以及GNSS、定位输出、底图的坐标系。
5. 用可测量地面目标覆盖悬停/移动/转向、俯拍/斜拍和变焦场景，统计P95/最大误差与无法定位比例；同时测真实落盘延迟和队列负载。

现有8181本来就在做单目几何定位（像素射线与地面求交）。这次解决的是旧遥测、时间窗口、框对应、异常容错和历史持久化问题；换一个单目算法不能自动补回缺失历史参数或消除时钟/标定误差。

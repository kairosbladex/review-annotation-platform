|---|---|---|

- 已用训练脚本的数据集契约校验（`_load_dataset_contract`）通过；四视图图片齐全。

## 构建规则

- 输入：`data/recheck-released-fp-20260930/dataset-source/candidate_pairs.jsonl` + `gold_labels.jsonl`（v1 的 142 条原样保留 + 新增），用 `scripts/prepare_ktd_clean_source_qwen_dataset.py` 生成；该脚本只新增“样本可指定自己的截图路径”，重建 v1 时标签、框与路径完全一致（个别图片像素因图像库版本差 1）。
- 与 v1 约定一致：截图为平台事件截图，干净帧为高清原片（视频最佳对齐帧 1920×1080 或无人机原图 4032×3024），框按单应矩阵投影。
- 排除：评测集样本 32（随机流量 200 与楼顶难例 108 中的框，保留给新模型评测）、看不清 3、与 v1 重复 58。
- 只纳入“车”：训练脚本按“类别|标签”等权抽样，卡车（只有误检）、两轮车、三轮车、公交车、违建样本过少或只有单一标签，会被过度重复或学成整类驳回；这 24 条另存 `other_class_*.jsonl`。
- 真目标按每个误检 3 个抽样（同事件优先），其余 307 条存 `reserve_*.jsonl`。原因：训练每轮抽样数等于训练行数，真目标过多会让“人员|真”等小组每轮重复过多；按此规则人员|真每轮约重复 4.2 次（v1 为 2.8 次）。

## 局限

- 误检仍少且集中：14 个车类误检来自少数几次飞行任务；验证集车类误检只有 3 个，不足以衡量误检拦截，应以 `data/vehicle-surface-gate-eval-20260929/resolution-ab-random`（随机流量 200，非车 19）和 `resolution-ab`（楼顶难例）评测新模型。
- 当前版本复检放过的 105 个目标中只有 2 个误检，新增误检大多来自旧版本放过的样本。
- 未训练、未评测；本目录只是数据。

# 人员候选框标注包（2026-10-08）

目的：为“人员”类复检准确率建立人工金标。目前人员只有 09-24 的 56 个金标（基础模型 + 旧提示词），无法评估现在的复检。

## 内容

- 111 个框、44 个事件，来自 7 次飞行任务（场景较集中，结论推广到其他航线前要注意）。
- 来源：09-24 测试环境全量快照（服务器 `codex-ktd-real-monitoring-20260924`）中全部 235 个“人员”候选：
  - 排除已有人工金标 56（`gold_overlap_map` + 训练/验证金标，按事件或图片 SHA 加 IoU≥0.5）；
  - 排除同一图片重复建事件的框 3；
  - 排除没有已核验高清原片的 64（多为未对上原视频的截图）；
  - 投影后落在原片画面外 1（`skipped.json`）。
- 高清素材：原视频 1920×1080（截图为 960×720，只清晰一倍），框中位大小约 22 像素；局部相似度 0.983～1.000。人很小，短视频是主要判断依据。
- 顺序已按固定种子 20261008 打乱；页面不显示检测置信度、复检结论或模型建议。

## 标完之后

- 测试环境人员框目前多数走旧版单图复核（视频事件没有干净原图），可直接对照测试库 `recheck_result` 算旧版在人员上的表现。
- 新版（原图 + Qwen）在人员上的表现需要离线回放：用本包的匹配原帧作为干净原图，按测试环境配置（人员不自动确认）在断网实例上跑。
- 看不清的比例本身也是结论：若很高，说明当前分辨率下人员复核只能转人工。

## 复现

服务器上：`scripts/collect_person_labeling_targets.py --gold <训练+验证金标 jsonl> --out <dir>`，再运行 `scripts/extract_hires_review_views.py --jobs jobs.jsonl --work-root <dir，含指向快照的 codex 软链接> --out <dir>/out --with-clips`。本次在断网、限 8GB 内存、4 核的临时容器中运行。高清素材（frames/crops/neighbors/clips，约 177MB）不入库。
